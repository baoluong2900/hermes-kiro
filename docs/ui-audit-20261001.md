# Kiro-Go Admin UI Audit — 2026-10-01

Branch: `fix/custom-claude-routing`. Live instance measured at `http://127.0.0.1:8080/admin`
(PID of `kiro-go-run` on port 8080). Audit done by measuring the **live rendered DOM**
(element box geometry + computed styles) across all 7 tabs in their **populated** state
(4 accounts, 500 log rows, 2 proxy rows, 3 API keys), plus a responsive sweep
1440 → 360px. Screenshots cross-checked each measurement.

## Method note — why not "20 subagents"

The entire admin UI is three tightly-coupled files: `web/index.html` (827 lines),
`web/app.js` (4,581 lines), `web/styles.css` (~3,880 lines). Fanning 20 agents out to
edit those same files in parallel would clobber each other and produce a broken tree.
Parallelism is only safe for **diagnosis** across independent screens — which was done by
measuring the live DOM directly, then applying coordinated fixes to the shared CSS.

## Findings

### 1. Logs table — cells shatter mid-token  ✅ FIXED
**Severity: high (main visible breakage).** On the Logs tab, every column had
`overflow-wrap: anywhere` (`.logs-table td`, styles.css:1367). Short structured values
broke mid-token across lines: status badge stacking vertically (成 / 功), `openai`→`openi`,
`claude-opus-4.8`, `107628ms`→`107628m`/`s`, masked account email. Rows rendered ragged
with uneven heights.

- Root cause: a blanket `overflow-wrap: anywhere` (originally added to stop long error-JSON
  forcing page-wide h-scroll) applied to *all* 10 columns. But `.logs-list` already scrolls
  both axes (`overflow:auto`, styles.css:1346), so cells never needed to self-break.
- Fix: `.logs-table td` → `white-space: nowrap`. `.log-msg` (error column) →
  `display:inline-block; max-width:32rem; white-space:normal` so long errors still wrap,
  bounded. Covers both renderers (app.js:813 and app.js:2184) via the shared class.
- Verified: `anyCellWrapped:false`, badge 36×19 not stacked, panel h-scrolls while page
  does not; error strings still wrap (`whiteSpace:normal`, bounded 512px).

### 2. Settings tab — page-wide horizontal scroll on mobile  ✅ FIXED
**Severity: medium (mobile only).** At ≤414px the "Áp Dụng Preset TuongTacFree
(không gồm API key)" button (`.btn.btn-outline`, 48-char label) kept its single-line
min-content width (392px) via `.btn { white-space: nowrap }` (styles.css:257), overflowing
a 380px viewport and forcing the whole page to scroll sideways (`pageHScroll:true`).

- Fix: scoped rule inside the existing `@media (max-width:720px)` block —
  `.btn { white-space:normal; max-width:100%; height:auto; min-height:2.25rem; ... }`.
  Buttons wrap and never exceed their container on narrow screens.
- Verified: mobile 390px Settings `pageHScroll:false`, button wraps to 3 lines within
  298px container (right edge 339 < 380). Desktop 1280px unchanged (`nowrap`, single line,
  save button untouched) — rule is media-scoped.

## Checked and NOT a bug

- **Desktop 768–1440px, all 7 tabs:** zero element spill, no page h-scroll, header aligned
  on one row. Clean.
- **Modals:** `.modal-content` is `flex-column` + `max-height:90vh`, `.modal-body` is
  `overflow-y:auto; min-height:0`. The open `addModal` is cleanly contained and scrolls
  internally. (An earlier "footer spills below" reading was a false positive — the selector
  had matched template nodes in other modals plus `body.modal-open`.)
- **Logs / API-Keys tables at mobile:** overflow is contained by their own `overflow:auto`
  wrapper; the page never h-scrolls. Working as designed.
- **Header nav wrapping at ≤600px:** intended responsive behavior (grid areas restack).

## Round 2 — parallel source audit (6 read-only subagents)

To honor the "divide the work" request safely, 6 read-only subagents audited independent
concerns (i18n, CSS quality, responsive, accessibility, app.js escaping, dark-theme), each
writing to `docs/ui-audit/`. All claims were re-verified against source + live DOM before
any edit. Confirmed real bugs were fixed; the rest are logged for follow-up.

### 3. Dark-theme badges — dead selectors  ✅ FIXED
**Severity: high.** Theme toggles via `.dark` on `<html>` (app.js:401), but 7 badge
overrides used `[data-theme="dark"] .foo` descendant selectors (styles.css:1405–1406,
1421–1425). `data-theme` only ever sits on the toggle buttons (styles.css:2991 — correct,
left intact), so those rules never matched: in dark mode, `.log-status--*` and `.err-badge--*`
rendered with light pastel backgrounds instead of the intended dark ones.
- Fix: `[data-theme="dark"] .foo` → `.dark .foo` for all 7.
- Verified live in dark mode: success badge computes `rgb(5,46,22)` / text `rgb(134,239,172)`,
  error badge `rgb(69,10,10)` — the intended dark values, previously dead.

### 4. Undefined CSS token `--border-color`  ✅ FIXED
**Severity: medium.** `.proxy-inventory-row` (styles.css:181) used
`var(--border-color, #333)` — `--border-color` is never defined (the real token is `--border`),
so it always fell back to hardcoded `#333`, a wrong border in light mode and non-adaptive.
- Fix: → `var(--border)`.

### 5. Two `<select>`s force mobile page h-scroll  ✅ FIXED
**Severity: medium (mobile).** `#apiKeyTraceSelect` (16rem min-width) and
`#channelsWindowSelect` (9rem min-width) carry inline widths the `.btn` mobile rule doesn't
reach, so they kept desktop width inside flex-wrap/grid cells on phones and could force
page-wide scroll at ≤320px.
- Fix: scoped `#apiKeyTraceSelect, #channelsWindowSelect { width:100%; min-width:0 }` inside
  the `@media (max-width:720px)` block.
- Verified: mobile 390px both tabs `pageHScroll:false`, `min-width:0` applies; desktop 1280px
  unchanged (select back to 160px, no h-scroll).

## Logged, NOT yet fixed (follow-up — mostly non-visual / lower risk)

These are real but lower-severity or need product decisions; recorded in `docs/ui-audit/`:
- **i18n:** External API/Model settings card (index.html:346–385) has ~11 hardcoded Vietnamese
  strings with no `data-i18n`; `sourceSwitcher` title hardcoded VN; `zh.json:523` embeds VN text;
  missing key `builderid.userCode`. (Content/translation decision — not a layout break.)
- **CSS quality:** a "late overrides" block (~styles.css:3800–3888) silently kills several
  earlier rules (`#logoutBtn` destructive style, `.help-block`, `.model-item` grid,
  `.model-name` mono font); one true duplicate `.help-block:last-of-type`; ~5 dead classes.
  Cosmetic / cleanup — no visible break confirmed.
- **Accessibility:** ~23 inputs without programmatic labels, 9 modals without
  `role="dialog"`/`aria-modal`/`aria-labelledby`, authenticated app has no heading hierarchy.
  Real a11y debt; larger structural change, logged for a dedicated pass.
- **app.js render:** escaping is actually consistent (no live XSS); two drifted log renderers
  (app.js:813 vs 2184) and one hardcoded badge (app.js:1084) are maintainability risks.
- **dark-theme (minor):** `.badge-power` near-black pill, `.batch-count`, `#logoutBtn` color
  are hardcoded/non-adaptive — low visual impact.
